# dsh-usage-insights — DSH 使用洞察

> 一个 UI 插件：在 web 界面里看清你的 DSH 正在怎么工作——哪些模块/技能被激活、哪些工具高频触发、
> 每个功能用了多少次，帮你评估各功能的**使用频率与价值**。
> 零 npm 依赖 · 纯本地 · 只读聚合（不修改任何会话数据）。

## 功能

打开仪表盘（见下），你会看到：

| 面板 | 内容 |
|---|---|
| 📊 概览 | 会话数 / 轮次 / 工具调用 / 错误 / 输入·输出·缓存读 token |
| 🧰 工具排行 | 每个工具的调用次数、频次条、错误率、平均耗时、最近使用；自动**价值分层**（核心/常用/低频/闲置/未用） |
| 🧩 当前组合激活状态 | 30 个服务探测（哪些能力 seam 活着）+ 模型可见工具名册（来自请求信封，标注"声明了但从未调用"） |
| 🎯 技能触发 | 哪些 skill 被模型实际调用过、多少次 |
| 🔌 MCP 服务器调用 | 按 `mcp__server__*` 前缀聚合的外部工具调用量 |
| 🧠 模型用量 | 按 provider/model 的调用数与 token（含缓存命中量——你的 KV cache 省了多少一目了然） |
| 📅 每日活动 | 按天的事件/工具调用时间线（排除流式碎片噪声） |
| 💬 最近会话 | 前 50 个会话的轮次/调用/token 概览 |
| 🧮 深层直方图 | 轮次终态（completed/error/interrupted/…）、注入来源（user/plugin/skill-catalog/…）、事件类型分布 |
| 📥 历史导入 | 一键把插件启用前的旧会话统计进来（增量：按存储修订号跳过未变化会话，永不双计） |

## 安装

```sh
# 方式一：从本目录（源码直装，无需构建）
dsh plugin --profile <你的 web profile> add /Users/Zhuanz/projects/jerry-personal/JerryDSH/plugin-dev/dsh-usage-insights

# 方式二：打 tarball 分发（无需构建权限）
cd 本目录 && npm pack && dsh plugin --profile <name> add ./dsh-usage-insights-0.1.0.tgz
```

装进 web profile 后重启，浏览器打开：

```
http://127.0.0.1:<你的端口>/usage-insights
```

headless 组合也可装：无界面路由，但统计照常采集落盘（`stats.json` 可直接被其它工具消费）。

## 使用

1. 打开仪表盘 → 点「📥 导入历史会话」→ 等进度走完（首次约 1-3 分钟/310 会话，之后秒级增量）。
2. 此后所有新会话实时计入（监听事件流，不重不漏）。
3. 「价值分层」口径：**核心**=7 天内 ≥20 次 · **常用**=14 天内有 · **低频**=30 天内有 · **闲置**=超 30 天 · **未用**=声明可见但从未调用。

## 配置（profile 的 cordis.patch.yml 里 id-targeted 覆盖）

| 键 | 默认 | 说明 |
|---|---|---|
| `dataDir` | 空 → `$DSH_HOME` | 统计数据目录（实际落盘在其下 `usage-insights/`：`stats.json` + `imported.json`） |
| `writeIntervalMs` | 30000 | 落盘间隔 |
| `flushEveryEvents` | 200 | 每累计 N 个事件额外落盘 |
| `skillToolName` | `skill` | 技能工具注册名（用于解析技能触发） |
| `snapshotTtlMs` | 60000 | 组合探测快照缓存时长 |

## 技术要点（为什么这样做）

- **数据源 = 官方事件流**：实时侧监听 `session/event`；历史侧走 `ctx.sessionPersistence` 的
  `listSnapshots()`（修订号）+ `inspect()`（官方解码器，自动解开 zstd 压缩帧与 chunk 打包行）。
  两条路共用同一个折叠函数，靠每会话单调 `seq` 去重——live、回填、重复回填互不双计（已实测验证）。
- **工具名册来自 `request/header` 信封**：工具按 agent 作用域注册，全局枚举为空；
  每次模型请求都会把完整工具 schema 记进日志信封，这是"模型真正看得见什么"的权威口径。
- **web 界面 = 宿主 webServer 的具名路由**（`/usage-insights` + 两个 API），SPA 之外独立成页，
  单文件自包含 HTML，无前端构建链。
- **零依赖 + 防御式读取**：不 import 任何 dsh 内部包（规避 dist-tag/Symbol 双实例坑），
  事件字段全部 duck-typing，坏数据跳过不崩。
- 统计口径升级用 `schema` 版本号管理：不兼容时整体重置重导，绝不新旧混算。

## 已知限制

- 工具"平均耗时"由 tool/call 与 tool/result 的时间差估算（秒级精度，受批内排队影响，看量级别看精确值）。
- 技能**目录**（可用技能清单）按作用域挂载，全局探测拿不到；面板显示的是"实际触发过的技能"。
- 组合里的 bundle/插件**行清单**当前 cordis 无公开枚举 API，用 30 项服务探测近似"哪些模块活着"。
- 仪表盘无鉴权，跟随宿主 webServer 的绑定面（默认仅回环地址，勿绑 0.0.0.0 暴露）。

## 实测记录（2026-08-30，dsh 0.1.1-rc.2）

- 隔离 web profile（3197 端口）连续 4 次冷启动路由稳定；310/310 历史会话全量导入零错误；
- 交叉验证：独立解压 transcript 计数 vs 插件计数——轮次/工具调用**精确一致**；
  事件总数差异由 chunk 打包行（物理行 vs 逻辑事件）解释，插件口径（官方解码器）为正确口径；
- 增量回填验证：二次导入只增加两次之间新产生的事件（+6 次调用），无双计；
- 落盘恢复验证：重启后统计从 `stats.json` 完整恢复。
