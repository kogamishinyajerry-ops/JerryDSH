## 二、P0 收尾只做确定的四项

1. `deployment/local-acceptance/run-local.sh`：启动失败必须传递非零退出码；启动成功需检查目标进程与服务。停止必须区分“已请求”“正在退出”“已退出”，只在确认退出后声称 stopped。保留 Docker 返回码 42 的负例，以及延迟退出 worker 的测试；不得使用 `|| true` 吞掉关键失败。
2. 把宿主执行和容器执行命令分别写清。修正 `launch-worker.sh` 的实际位置与调用方式，去掉对未交付的 `/opt/data/launch-worker.sh` 的依赖，或明确安装/挂载步骤。用全新数据目录验证。
3. headless 生成器必须接受实际 headless overlay 路径，不能继续硬编码 Web preset；使用绝对路径；配置导出与运行分开，`--dump-config` 不带任务参数。
4. 模板生成器在写文件之前校验 ref，拒绝路径穿越，确保目标解析路径始终位于指定 root 内。失败不能产生越界文件或污染 registry。

上次已关闭的三项——worker 领取前停止检查、授权信息恢复、项目配置覆盖——只做必要回归，不再重写。不得把部署脚本修复扩大成 STAR、HPC 或完整服务管理平台建设。

先整理已经产生的 r2 验收材料：实际运行版本、测试日志、父子会话与工具调用、人工授权和首次 runner 提交的事件顺序、真实 solver 的证据、取消退出证明、盲测的事前冻结/供参记录。缺什么写什么，不补造历史。压缩包给出精确文件名、SHA-256、文件清单，由用户上传验收对话；不能只说“包已打好”。P0 待外部证据审查不妨碍 P1 的只读盘点，但不能改为验收通过。

## 四、P1 第一批：真实语料试点

1. 在允许处理这些文档的内网机器上，对授权源目录做只读盘点。使用本包 `tools/inventory.py`，新输出目录放在源树外。实际文件、文件名、摘要和日志均按数据要求留在内网，禁止上传公开 GitHub、云端模型或当前外网验收会话。
2. `inventory_id` 只用于盘点，后端业务 doc_id 仍按 OA 的稳定标识/现有 ingest 规则映射。源 mtime 不能自动当作批准时间或有效版本。
3. 本包建议先做最多 200 份格式/目录多样、非重复且权限清楚的试点；样本可以调整，最终目标仍是约一万份。先确认 PDF/Office 的提取质量和可定位性，扫描件进入待 OCR 队列，不以空正文充当成功。
4. 扩展现有源适配器和 pipeline；原始文件只读，保留来源、原文摘要、提取器版本、页/段/表格定位。重复内容保留各自业务引用与授权范围，不合并成更宽权限。
5. 建立词法检索基线，再接实际 embedding/语义检索，比较同一标注集的前五条结果。降级时明确 `lexical-only`，不能写成 embedding 验收通过。
6. 使用内网已可用且获准使用的 DeepSeek/GLM 路由生成摘要/标签。模型输出是派生字段，不能覆盖原文或伪造作者、有效版本、批准结论；批处理预算、失败重试和断点续跑受控。
7. 查询主路径先返回文档清单、命中片段、版本/状态及出处。长摘要在 ingest 阶段处理，不让查询等待长文生成。统一延迟计时包含查询 embedding、检索、传输和文档列表呈现。

权限沿用现有受信服务账号/数据分区，先把授权清楚的一个分区做完整。模型自己填写的 `domains`、`filters`、actor 不能授予权限。检索、全文、摘要、缓存使用同一范围。没有可信权限信息的文档隔离，不采用“默认所有人可读”。

## 五、把验收做成别人拿到就能复核

先由工程师标注一组问题与相关文档，建议 30 题，包含专业术语、同义问法、版本区别、跨文档、无答案和越权负例。开发集与保留集分开，修复中用过的题目转为开发集。模型可生成候选题，不能自行给全部结果打真值标签。

建立本地记录适配器，把真实 query 响应映射为本包 `docs/RECORD-FORMAT.md`。保留真实原始响应的本地文件及摘要，记录后端 build、snapshot_id、查询 ID、trial ID、端到端耗时。别把合成示例里的时延复制进去。

建议的试点门槛（允许根据真实语料在评测前冻结调整）：
- 宏平均 Hit@5 ≥ 80%，同时报告标注集 Recall@5；
- 每题至少三次热查询，每次完整文档清单响应 ≤ 3000 ms；报告 p50/p95/max，冷启动单列；
- 无答案不编造文档，指定越权文档不进入结果/全文/摘要；
- 原文定位抽查全部可复核；
- 同批重入幂等，修改有新版本，删除/撤回/权限变化不保留可访问残影；
- stage/validate/publish/rollback 复用已有机制，验证原子快照与回滚；权限撤回不能被缓存或回滚重新暴露。

发布/回滚中的 `confirm:true` 只是请求字段，不单独算人审凭据。核查后端受信确认方式，必要时让我在本地确认具体快照，不允许模型自授批准。

200 份真实试点通过后，再分批导入一万份目标语料，分别报告批量失败、索引规模与查询时延。合成规模测试、小样本结果、内网全量结果必须分栏，不能互相替代。
