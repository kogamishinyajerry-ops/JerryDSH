# P1 知识库 v1 · 实施规格

## 1. 目标与复用位置

遵循交接文件 P0 → P1 → P2 的顺序。本轮将 P0 剩余部署修复列为封板任务；知识库的数据盘点和样本准备可以独立开展，但不以 P1 的进展抵消 P0 的待验收项。

v1 场景：工程师输入“APU 启动机过热的历史处理”，返回相关文档清单和可定位原文。这里只定义检索任务，不生成实际工程处置建议。

预期链路：

```text
原 OA 文件（只读、内网）
  → 文件清单 / OA ID / 权限分区 / 原始摘要
  → 复用 civair-kb 的提取与清洗 → 保留定位的文本片段
  → 分类、摘要、标签（派生字段与原文分离）
  → 现有词法检索 + 已核验内网 embedding 的语义检索
  → stage → validate → 人工发布 → 快照切换 / 回滚
  → 现有 jerry-aero / kb-civair 查询入口
  → 文档列表、版本/状态、命中片段、原文位置
```

已见 DSH 代理的入口：`civair_kb_query/get/cross/status/update/gaps/propose`，请求发给 HTTP sidecar。代理说明当前查询为 BM25；本轮尚未取得后端代码，不能声称它没有向量检索，也不能把代理注释当作后端的权限或事务证明。

后端找到后，扩展其现有 source adapter。拟新增 OA 域命名由实际 registry 决定；`oa_documents` 仅是讨论名称，不能直接假设后端已经接受。

## 2. 有限封板：P0 收尾

只处理已确定的四项：启动失败返回非零、停止结果与真实退出一致；宿主/容器脚本路径完整；headless overlay 的生成及 `--dump-config` 命令可独立运行；模板 ref 的写入前路径约束。

用独立提交/PR，保留失败回归和退出码证据。r2 证据先交付再审查；未取得材料的部分保持 NOT_VERIFIED。不要重新打开已经验收关闭的核心停止、授权恢复和项目配置问题，除非出现新失败。

## 3. P1-0：资产与数据盘点

检查 `CIVAIR_KB_HOME`、`CIVAIR_KB_STORE`、`CIVAIR_KB_PYTHON`、`CIVAIR_KB_URL` 的实际配置，不导出凭证。源码中原 Mac 路径只是定位线索，不能写成新默认值。

输出后端 reuse-map：解析器、原文定位、增量/去重、词法检索、embedding、发布/回滚、权限分区、查询缓存和返回格式分别在哪里，是否实测。已有能力直接复用，只新增缺口。

在允许处理 OA 文档的机器上盘点：文件数量/大小/类型、读失败、重复组、缺少 OA 元数据的比例。扩展名不是解析成功的证据。对少量样本实际提取以判断扫描件和复杂表格；此步骤仍不得上传真实内容。

## 4. P1-1：可检索试点

本包建议先取最多 200 份非重复、来源和权限可确认的试点文档。先用盘点工具做格式/目录分层选择，再由当地工程师修正专业覆盖。这个数字可以依真实语料调整。

必须记录：OA 稳定 ID（若原系统有）、源系统/定位、原始文件摘要、提取器版本、文档版本/状态/日期的来源、可用权限分区。缺失字段保留 unknown，不让模型补造作者、批准、有效版本。

复用已有解析器；增补的解析需保留 PDF 页/段落、Office 标题段落/表格单元或表格工作表/行等定位。暂时不支持的文件记录具体原因和比例。扫描件只进入明确的待 OCR 队列，不能当作空文档成功入库。

去重处理：相同内容可共享内容存储，但来源引用、OA ID、版本和授权不合并为更宽权限。任何权限不明或来源不明文档进入隔离清单。

先建立现有 BM25 基线，保留原始结果。随后接实际可用的内网 embedding 服务/本地模型，核对真实模型名、维数、截断行为和批量失败。DeepSeek/GLM Flash 的生成接口与 embedding 接口分别核验，不自行假设二者相同。

摘要和标签在入库阶段异步生成，失败可重试且不覆盖原文；查询的三秒预算中不等待长篇摘要生成。v1 最终仍需实测 embedding/语义检索链路，词法单一路径只算基线或明确标记的降级运行。

## 5. P1-2：检索、更新与证据

沿用现有工具入口和后端查询/全文协议，新增返回字段保持向后兼容。建议每条结果提供：真实 doc_id、标题、版本/状态（若来源有）、原文定位、命中片段、摘要出处、snapshot_id、检索模式。

权限由可信的服务配置/主体映射约束，不能相信模型请求中的任意 `domains`、`filters`、actor 或 scope。小团队试点可用既有服务账号及物理分区方式，不要求先造完整企业 IdP；要把限制写清楚，搜索、全文、缓存和派生摘要保持同一分区。

新增、修改、删除、撤回、权限变更都要演练。查询要么看到旧快照，要么看到已验证的新快照；不能看到一半旧一半新。权限撤回不能因为缓存或回滚重新暴露文档。文档正文包含“忽略前文”“执行命令”等文本时，它们只能作为待检索内容处理。

发布与回滚复用已有受信流程；代理中的 `confirm:true` 只是请求字段，不足以单独证明真实人工已批准。核验后端控制，不为达成演示自动批准。

## 6. 提议的试点验收门槛

以下是实施建议，不是既有实测结果：

| 维度 | 门槛/记录 |
|---|---|
| 解析与来源 | 试点文件全部有明确状态；成功提取结果逐条可回到原文；抽查页/段/表格定位 |
| 相关性 | 建议 30 道人工标注检索问题；独立保留集；宏平均 Hit@5 ≥ 80%，同时报告标注集 Recall@5 |
| 时延 | 每题至少 3 次热查询；从发送到呈现文档清单记录全时延，逐次检查 ≤ 3000 ms；p50/p95/max 均报告；冷启动单列 |
| 空结果 | 不存在答案时不编造文档，保留 0 命中及原因 |
| 权限 | 列出的越权文档不得出现在结果/全文/摘要/计数中；另做缓存和权限撤回测试 |
| 增量 | 同批重入幂等；修改出新版本；删除/撤回不留可访问残影 |
| 运维 | 源只读；发布可回滚；失败保留现场；新环境按说明能启动 |
| 规模 | 200 份真实试点与一万份目标数据实测分开，不从小样本时延外推一万份 |

`tools/evaluate.py` 只检查输入记录能计算的部分：标签相关性、时延、错误、已列 forbidden IDs、引用格式。权限撤回、真实原文定位、模型来源真实性、发布原子性仍要独立行为测试，不能被一份 PASS JSON 替代。

保留集只在代码/查询规则冻结后评测；用来指导修复的题目转为开发集。模型可起草候选问题，不能作为唯一的事实标注者与裁决者。

## 7. 本阶段不做

不重写 DSH，不另建 KB 平台，不堆新的知识插件，不把全体会话历史自动汇入业务知识库，不做完整企业本体，不做精细 UI 工作台，不扩大到 STAR/MPI/HPC，不以公开数据冒充真实内网验证。P2 的任务视图仍后置。
